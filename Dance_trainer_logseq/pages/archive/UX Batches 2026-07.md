- ## Reading the score
	- 17/40 lands in the rubric's "Poor" band, which overstates it. Heuristics 6 (recognition), 9 (error recovery) and 10 (help) are scored against a general-audience bar, and a single-expert-user tool legitimately underinvests there.
	- The deterministic slop detector returned **zero findings** across ~5,100 lines of hand-written SFCs, verified against a synthetic control file. The codebase does not reach for template reflexes; the gap is information design, not craft.
	- **The critique's own error rate turned out to be high.** Four of its findings were factually wrong (see "## Corrections to the critique"), one proposed fix didn't satisfy its own finding, and two guarded states that can't be reached on the real board. Treat future critique output as a set of proposals to verify, not a task list.
- ## The session model — decided 2026-07-21
	- The practice surface is a **continuous work model**. There is no day boundary, no session expiry, no midnight anything, and the store deliberately stores no `Date`. This was an explicit decision, not an oversight.
	- Two states, and they are the whole model:
		- **being trained** — what's queued to practise now
		- **trained, awaiting sort** — practised, and needing to be sorted back into spaced repetition via [[Practice Companion View]]'s Session Review
	- Vocabulary follows from that: the container is a **"practice queue"**, and the done group gets a labelled **"TO SORT (n)"** header. The word "today's" comes out of all seven user-facing strings.
	- This **supersedes** the critique's proposal to stamp the session and expire it at local midnight. Expiry would only ever delete an *unfinished* session — `resolveCard()` already empties a session you actually run through Review — and the done-but-unreviewed cards it would silently discard are exactly the ones whose practice hasn't been recorded into the schedule yet.

- ## Found while implementing
	- ### Deviations from the agreed plan
		- **"Keep in place" applies the card's own column's offset, not always today.** The interview agreed "stamp `due_date = today`", framed around the Due column. But the button is shown for a card in *any* column, and stamping today on a card sitting in Wöchentlich makes that column's interval a lie and bounces the card straight back out on the next sweep. `recordPracticeInPlace()` uses `due_offset_days` when the column has one — which reduces to exactly the agreed behaviour for the Due column, whose offset is `null`. The button label now names the actual column ("Keep in Today") instead of the hardcoded "Keep in Due".
		- **`boardFormat.ts` does round-trip the two new fields.** Left open in the plan; decided yes. The export is offered in the UI as a backup, and silently dropping months of practice history on restore is data loss. `lastScheduledColumnRef` resolves through the same localId map as `columnRef`, so it survives the id remapping; the Trello parser writes both as `null`.
		- **`.field-label` went to `--color-ink-dim`, not `--color-ember-text`.** Batch 6 asked for both "paint ember-as-text with the new token" and "fix the eyebrow hierarchy inversion". Ember-text passes contrast (5.01) but keeps an accent colour shouting four times down one dialog, so the hierarchy fix won. Also applied to `ColumnSettingsModal.vue`, which carried a byte-identical copy at 2.78:1.
		- **Label `sage` was lightened** `#6e8b6b` → `#7d9a7a`. It was the one fill no text colour could clear — 3.77 against white, 4.06 against ink. At the new value ink reaches **4.94**. This changes how existing sage labels look; every other label colour is untouched.
		- **Modal link-chip fill dropped 18% → 10% ember.** `--color-ember-text` is only 4.17:1 on the 18% tint, still under the floor a 10px chip needs. At 10% it's 4.52. The dark practice chip stays at 18% — it already passes at 7.84.
		- **`dueLabel()` lost its `Jul 5` branch** — it is purely relative now (`3d late` / `today` / `in 4d` / `in 24d`). The native `<input type="date">` in the modal still renders `04.06.2026` per browser locale; that control isn't formattable without replacing it.
	- ### Defects found that weren't in the critique
		- **"Keep in Due" never rescheduled anything.** `resolve(null)` skipped `moveCard` entirely, so a practised-and-kept card's due date was never touched and its lateness climbed forever. Found reading `boardStore.moveCard`. This is why every card in the real board's Today column reads as overdue.
		- **`.md-link-chip` was `display: inline-flex`, so `text-overflow` never applied** — its text was an anonymous flex item and the chip hard-clipped with no ellipsis at all. Switched to `inline-block`, with the `▶` absolutely positioned so the RTL head-truncation can't drag it to the far side.
		- **`renderMarkdownWithLinkChips()` was built on top of `renderMarkdown()`**, so stripping `href` in the latter (Batch 7) would have killed the chips' links in the card modal and practice view too. It now runs its own pass.
		- **`PracticeFocusCard`'s `.note-preview` had the same inverted colour base** as `.desc-preview` did before 2026-07-21 — base `--pc-ink-dim` with only `p`/`ul`/`ol` overridden back, so markdown headings rendered *dimmer* than the body under them. Same fix: base ink, `.placeholder` the one exception.
	- ### Corrections to this page's own claims
		- **The topbar declutter does not un-truncate the board name on mobile.** See Batch 5 above — measured, not assumed. The claim was written from the desktop layout and never checked at phone width.
	- ### Shipped short of the plan
		- **Toasts got no recovery action.** Dismiss, a 10s hold for errors, variants, and demoting the raw Supabase string below a headline all shipped. A retry action needs the failed operation as a callback at each of the 28 `show()` call sites, and was not built.
		- **Error copy is still generic.** Every error reads "That didn't go through" with the raw Supabase string as detail underneath. Per-action copy (`Could not rename that column`) means editing all 28 call sites in `boardStore.ts` / `authStore.ts` — mechanical, not done.
		- Both carried to [[Open Work]] (2026-07-25): per-action error copy + retry actions, and the board name truncating at phone width.
- ## Decided against
	- CANCELED **Auto-seeding the session.** The critique wanted a primary "Start with today's due cards" that seeds the queue in one tap. Rejected outright: *"I just want to see what's due and be able to quickly choose stuff that I want to practise. I don't want any automatic seeding."* This is why Batch 2 (the drawer) is the real P0 rather than the empty state.
	- CANCELED **Midnight session expiry.** Superseded by the continuous work model above.
	- CANCELED **Toast + Undo after each Review resolve.** Considered and declined. Known consequence, accepted: a mis-tap in Review is silent and permanent, and the only recovery is finding the card on the board and dragging it back.
	- CANCELED **Interval labels on the Review bucket buttons** (`Wöchentlich · +7d`) and **capping visible buckets at 4.** The real board has 6 quick targets, all genuinely in use (2 Monatlich holds 10 cards), so a cap would hide real destinations behind an extra tap.
	- CANCELED **Surfacing `due_offset_days` in column headers.** Same call as the bucket labels.
	- CANCELED **Building SM2.** It would replace the Review flow — the algorithm would pick the interval, removing the manual choice of destination column that is the whole point of Review. Docs get fixed instead; see below.
	- CANCELED **Darkening every hairline border.** The critique's own proposed value `#c9bda8` computes **1.41** against the 3.0 it demands — the fix doesn't satisfy the finding. Reaching 3:1 against `--color-bg` needs a roughly mid-grey hairline that would make the board look like a wireframe, and WCAG 1.4.11 is about UI boundaries needed to *understand* content, not decorative rules.
	- CANCELED **Focusable task cards and column titles, focus traps in the four overlays, enlarged touch targets.** 77 cards and 13 column titles are click-handled `<div>`/`<h2>`s; the four overlays trap nothing; 13 `⚙` buttons are 32×32 and `.add-label-btn` is 26×26. All real, all declined for a single-user touch-first tool. The keyboard work that *was* wanted is the search selection in Batch 2.
	- CANCELED **"No quick-target columns" empty state in Review.** Unreachable: the board has seven quick targets. Same reasoning that killed the `is_due_column` fallback item on 2026-07-21.
	- CANCELED **Column tag on add-drawer rows.** Would be needed to tell a due hit from a scheduled one in cross-column search results — but the `dueLabel()` text in Batch 2 already answers that (`in 24d` reads as clearly not-due).

	- **[[PROJECT_HANDOFF]] isn't a false claim about the app** — it's explicitly "the raw spec" for the v1→v2 rebuild, describing an intended 5-status / SM2 / focus-XP system that was never built. It's been marked as superseded rather than gutted; the divergence is the decision, and the spec is the record of what was considered.
	- **The label-chip finding is one ratio where there are six.** It reports `#fff` on label fills as "3.43 / 3.77". Actually: rose 4.81 ✓, plum 6.19 ✓, denim 4.47 ✓, brass 2.93 ✗, ochre 3.12 ✗, sage 3.77 ✗. No single text colour fixes it.

	- Earlier corrections from the Tier 1 pass, kept for the record: the add-drawer shift was diagnosed as "~38px on every tap" when the measured reality was rows *above* the tap moving +51px and rows *below* +3px, two forces partly cancelling; and the `is_due_column` warning would have guarded a state the real board never reaches.
