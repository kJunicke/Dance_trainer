- ## Unconfirmed — found by reading, never reproduced
	- Raised 2026-07-25 while writing [[Board View]]. Each was found in the code, none has been seen happen. Confirm in the browser against *Test board* before fixing anything here.
	- TODO Dragging a card **upwards within its own column** may land it one slot below the insertion line. `moveCard` assigns `position = targetPosition` and then re-sorts, so the moved card ties with the card already holding that position, and the stable sort breaks the tie by the order of `cards.value` — i.e. by DB load order, not by the drag. Replaying the store's exact logic in a scratch script on `c0..c4,X` dropping X before `c2` produced `c0,c1,c2,X,c3,c4`. Downward and cross-column drops come out right, cross-column arguably by luck. Fix would be an explicit splice instead of assign-then-sort. See [[Board View]].

- ## App — features deferred
	- TODO Quick-note in Session Review that can append to *any* card's description, not only the card being reviewed. See [[Practice Companion View]].
	- TODO Nextcloud share links render with the URL as their visible text instead of the filename. Needs a Supabase Edge Function (the share page is CORS-blocked client-side) plus somewhere to cache the result — and confirmation that those pages actually expose `og:title`. **Not urgent:** head-truncating the chip already shows the distinguishing tail, which was the real complaint. See [[Card Notes]].
	- TODO Own the mobile board's horizontal fling in JS, so a swipe travels a *repeatable* number of columns. Raised 2026-07-26: swipe distance currently varies for flicks that feel identical, and no CSS setting can change that — see [[Board View]] for the mechanism and for why `scroll-snap-stop: always` was rejected as the cheap fix. Shape agreed but not built: `scroll-snap-stop: always` to make the browser guarantee the single-column case, plus passive touch listeners on `.board` measuring release velocity; below a threshold do nothing at all, above it compute `steps = round(velocity × K)`, disable snap, rAF-animate `scrollLeft` to that column with an ease-out, re-enable snap. ~30 lines in `BoardView.vue`, replacing the browser's hidden decay curve and quantizer with `THRESHOLD`, `K` and a duration that can be tuned by feel. **Needs a real device** — the whole point is feel, and none of it can be judged from a desktop iframe (see Verification debt below).
	- TODO `splitBlocks()` shares the CRLF offset-drift flaw that was fixed in the split/merge transforms: `marked.lexer()` normalises line endings before tokenising, so token `raw` lengths stop summing to the source length and every derived offset drifts one byte per `\r`. Per-block editing of a CRLF note therefore splices at the wrong place. Not reproduced in real use — nothing in the app authors CRLF — but a Trello import can carry it in, and editing preserves it. Fix is the same `toLf()` at the top of the walk. See [[Card Notes]].
	- TODO **Make a parted card look different from an unparted one on the board face.** The lineage is the card's identity, not context — `Hammers › Posture` and `Drops › Posture` are both stored as "Posture" — yet it renders as the smallest, dimmest thing on the card. Six treatments were prototyped 2026-07-26 in the app's real tokens at true column width and **none was accepted**: stacked title (promote the line to the display face), filed-under (a folder tab notched onto the card's top edge), family key (monogram tile in a colour hashed from the parent name), nameplate (full-bleed tinted band across the card head), inline mark (mono, in `--color-ember-text`), outline (indent plus a tree elbow). The finding worth keeping: only the tab and the nameplate change the card's **silhouette**, and silhouette is what fixes *scanning* — every other option is a variation on more legible small text, which only fixes reading. Three were rejected on principle rather than taste: the family key overloads a face that already spends colour on the status rail and label chips; the outline draws a tree that isn't there, since parts are scattered by schedule rather than filed under their parent; the inline mark spends the ember *action* colour on decoration. The practice surfaces were solved separately and are **not** blocked on this — see [[Card Relationships]].
	- TODO Quick access to a card's siblings mid-session, and whether the practice add drawer should match composed names the way the board search now does (it currently searches the stored leaf name and only *displays* the chain). **Any sibling access must stay read-only**: a jump that also *queues* the sibling turns a planned session into a family run — blocked practice, which is right while a part is raw and wrong once it's stable. The evidence is contested in applied settings, so the argument is "don't make it the one-tap default", not a prohibition. See [[Card Relationships]].
	- TODO Sibling order in the family tree is `position` order, inherited from the column. Revisit only if it reads wrong — there's no separate ordering for parts. See [[Card Relationships]].
	- TODO Split `list_item`s into separately-editable blocks in the note editor. Today one `marked` token is one block, so clicking any bullet opens the whole list's raw source. Shipped that way deliberately to find out whether it grates. See [[Card Notes]].
